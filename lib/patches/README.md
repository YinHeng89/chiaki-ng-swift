# SDL3 DualSense extension

This is a project-local modification of SDL 3.4.16, not an upstream SDL feature. SDL retains its original zlib licence and copyright notices. SDL.cmake pins the release archive and hash; ApplySDL.cmake applies the reviewed patch or verifies that it is already present. A changed upstream integration point fails configuration.

The PS5 HIDAPI driver recognizes an application-specific eight-byte CNH1 command. Operation zero probes without writing to hardware, one enables experimental waveform output, and two disables it and expires pending waveform requests. Only PlayStation controllers 054c:0ce6 and 054c:0df2 over Bluetooth pass this gate. Regular applications and controllers retain the ordinary effect path unless explicitly enabled.

Operation one is idempotent: enabling an already enabled controller succeeds without another write, so a stream that regains focus keeps its Bluetooth route. The neutral effect that enters waveform mode is queued before the mode is set, so it is not subject to the waveform queue limit.

The extension accepts 78-byte report 0x31 carrying two sub-packets: 0x11 (header 0x91, length 6, flags 0x7e, four start-threshold bytes and a counter) and 0x12 (header 0x92, length in bytes, at most 62 bytes, 31 stereo frames). The driver owns the shared four-bit sequence, the counter and the CRC. While enabled, ordinary state effects preserve native haptic selection and zero motor amplitudes. Both packet types use SDL's existing HID worker and device lifetime lock; no second raw-HID writer opens the controller.

Waveform submissions are paced by the controller's own input reports. Each Bluetooth 0x31 input report grants one send credit, capped at two, and each accepted waveform report spends one. Byte 65 of that input report is the controller's buffered haptic audio in milliseconds; submissions are refused while it exceeds 40. They are also refused when two device requests are outstanding, expire after 40 ms in the worker, are never coalesced as motor state and skip the worker's 10 ms fairness delay. Ordinary native-mode effects are capped at four. Already executing writes cannot be revoked.

No other library or service dependency is linked. The bridge converts little-endian signed 16-bit feedback at 3 kHz with bounded gain into signed eight-bit stereo frames, keeps at most 96 frames and discards a remainder older than 30 ms, so a slow link drops audio rather than accumulating latency. Adaptive trigger effects use SDL's existing 47-byte PS5 effect format.

Chiaki's PS5 session negotiation enables DualSense when an extended-feedback preference is enabled. Its haptic sink accumulates at most 512 bytes, drops malformed or stale data, and exposes 256-byte blocks plus latest trigger state to the bounded input poll. There is no per-packet dispatch to TCA or an unbounded main-queue callback chain. Console intensity settings and controller preferences scale feedback. Stop, focus loss and switching devices disable waveform mode and neutralize effects. Preferences remain off by default; unsupported waveform activation leaves standard rumble active.

Controls configuration remains payload version 1. These are additive optional fields: nativeHapticsEnabled, hapticStrength and adaptiveTriggersEnabled. Legacy documents decode them as false, 0.7 and false without rewriting saved mappings. Numeric validation still runs before persistence and stream activation.

## Verification boundary

Native tests cover PCM signs and gain, packet offsets, trigger ordering, unsupported-device rejection, fragmented input, bounded overflow, expiry, cancellation and intensity routing. Swift tests cover preference decoding and round trips. Building and static analysis validate integration with the pinned SDL driver. Queue acceptance is not a HID-write acknowledgement, and neither proves actuator response. SDL's inherited worker does not return individual HID-write results to the app. Probe measurements on one Bluetooth DualSense with the controller resting and macOS outside Game Mode showed that the link carried about one 78-byte output report per 15 ms input interval, so this format reaches about 0.69 of real time there. With Chiaki-ng full screen in Game Mode the interval drops to 7.5 ms and the same reports reach about 1.36 times real time; on that link the user judged the feel close to the wired route. Simultaneous effects and physical latency remain unverified; the GUI labels native output experimental.

To validate on hardware, select the intended DualSense, connect it over Bluetooth, enable native haptics under Controls / Controllers / Haptics, save and start a new PS5 stream. Check waveform feedback, intensity/off settings, triggers, focus loss, disconnection and reconnection. Over USB the app does not use this patch for haptics: it plays the waveform through the controller's USB audio channels (`lib/bridge/haptic_audio.c`), and this patch only carries adaptive triggers and standard effects there.
